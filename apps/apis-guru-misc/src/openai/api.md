## Answers the specified question using the provided documents and examples. The endpoint first [searches](/docs/api-reference/searches) over provided documents or files to find relevant context. The relevant context is combined with the provided examples and question to create the prompt for [completion](/docs/api-reference/completions).

<a id="opIdcreateAnswer"></a>

> Code samples

```bash
curl https://example.com/answers \
  -X POST \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "documents": "['\''Japan is an island country in East Asia, located in the northwest Pacific Ocean.'\'', '\''Tokyo is the capital and most populous prefecture of Japan.'\'']",
    "examples": "[['\''What is the capital of Canada?'\'', '\''Ottawa'\''], ['\''Which province is Ottawa in?'\'', '\''Ontario'\'']]",
    "examples_context": "Ottawa, Canada'\''s capital, is located in the east of southern Ontario, near the city of Montréal and the U.S. border.",
    "expand": [],
    "file": "string",
    "logit_bias": null,
    "logprobs": null,
    "max_rerank": 200,
    "max_tokens": 16,
    "model": "string",
    "n": 1,
    "question": "What is the capital of Japan?",
    "return_metadata": false,
    "return_prompt": false,
    "search_model": "ada",
    "stop": null,
    "temperature": 0,
    "user": "user-1234"
  }'
```

## Transcribes audio into the input language.

<a id="opIdcreateTranscription"></a>

> Code samples

```bash
curl https://example.com/audio/transcriptions \
  -X POST \
  -H 'Accept: application/json' \
  -F 'file=@/path/to/file' \
  -F 'language=string' \
  -F 'model=string' \
  -F 'prompt=string' \
  -F 'response_format=json' \
  -F 'temperature=0'
```

`POST /audio/transcriptions`

> Body parameter

```yaml
file: string
language: string
model: string
prompt: string
response_format: json
temperature: 0
```

<h3 id="transcribes-audio-into-the-input-language-parameters">Parameters</h3>

|Name|In|Type|Required|Description|
|---|---|---|---|---|
|body|body|[CreateTranscriptionRequest](#schemacreatetranscriptionrequest)|true|none|
|» file|body|string(binary)|true|The audio file to transcribe, in one of these formats: mp3, mp4, mpeg, mpga, m4a, wav, or webm.<br>|
|» language|body|string|false|The language of the input audio. Supplying the input language in [ISO-639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes) format will improve accuracy and latency.<br>|
|» model|body|string|true|ID of the model to use. Only `whisper-1` is currently available.<br>|
|» prompt|body|string|false|An optional text to guide the model's style or continue a previous audio segment. The [prompt](/docs/guides/speech-to-text/prompting) should match the audio language.<br>|
|» response_format|body|string|false|The format of the transcript output, in one of these options: json, text, srt, verbose_json, or vtt.<br>|
|» temperature|body|number|false|The sampling temperature, between 0 and 1. Higher values like 0.8 will make the output more random, while lower values like 0.2 will make it more focused and deterministic. If set to 0, the model will use [log probability](https://en.wikipedia.org/wiki/Log_probability) to automatically increase the temperature until certain thresholds are hit.<br>|

> Example responses

> 200 Response

```json
{
  "text": "string"
}
```

|Status|Meaning|Description|Schema|
|---|---|---|---|

## Classifies the specified `query` using provided examples. The endpoint first [searches](/docs/api-reference/searches) over the labeled examples to select the ones most relevant for the particular query. Then, the relevant examples are combined with the query to construct a prompt to produce the final label via the [completions](/docs/api-reference/completions) endpoint. Labeled examples can be provided via an uploaded `file`, or explicitly listed in the request using the `examples` parameter for quick tests and small scale use cases.

<a id="opIdcreateClassification"></a>

> Code samples

```bash
curl https://example.com/classifications \
  -X POST \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{
    "examples": "[['\''Do not see this film.'\'', '\''Negative'\''], ['\''Smart, provocative and blisteringly funny.'\'', '\''Positive'\'']]",
    "expand": [],
    "file": "string",
    "labels": [
      "Positive",
      "Negative"
    ],
    "logit_bias": null,
    "logprobs": null,
    "max_examples": 200,
    "model": "string",
    "query": "The plot is not very attractive.",
    "return_metadata": false,
    "return_prompt": false,
    "search_model": "ada",
    "temperature": 0,
    "user": "user-1234"
  }'
```

`POST /classifications`

<aside class="warning">
This operation is deprecated

## The search endpoint computes similarity scores between provided query and documents. Documents can be passed directly to the API if there are no more than 200 of them. To go beyond the 200 document limit, documents can be processed offline and then used for efficient retrieval at query time. When `file` is set, the search endpoint searches over all the documents in the given file and returns up to the `max_rerank` number of documents. These documents will be returned along with their search scores. The similarity score is a positive score that usually ranges from 0 to 300 (but can sometimes go higher), where a score above 200 usually means the document is semantically similar to the query.
