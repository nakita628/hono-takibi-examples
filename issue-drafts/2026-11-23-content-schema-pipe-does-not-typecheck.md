# zod: `contentMediaType` + `contentSchema` on a string emits `z.string().pipe(<object schema>)`, which does not type-check

## What

A string property with `contentMediaType: application/json` and a `contentSchema` is generated as
`z.string().pipe(PayloadSchema)`. `.pipe()` needs a schema whose input type is `string`, but
`PayloadSchema` is an object schema, so `tsc` fails with TS2345. The string is also never parsed as JSON
before the pipe, so even without the type error every value would fail validation at runtime.

## Where

zod generation for string schemas that have `contentSchema` (OpenAPI 3.1 / JSON Schema 2020-12 `contentSchema`).

## When

Every run on an OpenAPI 3.1 document that uses `contentMediaType` + `contentSchema`. Found in the
OpenFeature Remote Evaluation Protocol spec
(https://github.com/open-feature/protocol/blob/98c4e0de5583c0d79dd938b82975c80125335e92/service/openapi.yaml,
`components.schemas.sseEvent.properties.data`).

## Who

- hono-takibi 0.33.1
- Node.js v22.23.5
- Linux

## How

`openapi.yaml` (31 lines):

```yaml
openapi: 3.1.0
info:
  title: contentSchema
  version: 1.0.0
paths:
  /event:
    get:
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Event'
components:
  schemas:
    Event:
      type: object
      required: [data]
      properties:
        data:
          type: string
          contentMediaType: application/json
          contentSchema:
            $ref: '#/components/schemas/Payload'
    Payload:
      type: object
      required: [type]
      properties:
        type:
          type: string
```

Command:

```bash
npx hono-takibi openapi.yaml -o src/routes.ts
npx tsc --noEmit   # strict, moduleResolution Bundler
```

Actual output (excerpt):

```ts
const EventSchema = z
  .object({ data: z.string().pipe(PayloadSchema) })
  .openapi({ required: ['data'] })
  .openapi('Event')
```

```
src/routes.ts(9,35): error TS2345: Argument of type 'ZodObject<{ type: ZodString; }, $strip>' is not assignable to parameter of type '$ZodType<any, string, $ZodTypeInternals<any, string>>'.
  The types of '_zod.input' are incompatible between these types.
    Type '{ type: string; }' is not assignable to type 'string'.
```

Expected: output that type-checks. JSON Schema treats `contentMediaType` / `contentSchema` as annotations
that do not have to be asserted, so plain `z.string()` would be correct. A version that does validate would
need to parse the JSON before the pipe (for example a transform that runs `JSON.parse`).

## Why

The generated routes do not compile, and nothing in the output can be used without editing it by hand.
