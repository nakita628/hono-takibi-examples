# Handler stubs from `template` do not typecheck, so `client` / `rpc` / hooks projects fail `tsc` until every handler is written

## Summary

`template` writes each handler with an empty body. With @hono/zod-openapi's typed handlers an empty body is a type
error, one per operation:

| template | stub | error |
| --- | --- | --- |
| `{}` | `app.openapi(route, (c) => {})` | TS2345 |
| `{ routeHandler: true }` | `RouteHandler<typeof route> = async (c) => {}` | TS2322 |
| `{ define: true }` | `defineOpenAPIRoute({ route, handler: async (c) => {} })` | TS2322 |

`client` needs `template` and is typed through the template's `src/index.ts`, which imports the handlers.
So every project that generates `client`, `rpc` or any hook fails `tsc --noEmit` as generated: 7 errors for the
Train Travel API, 92 for the Memos API (0.32.5).

## Reproduction

`openapi.yaml`:

```yaml
openapi: 3.1.0
info:
  title: client-repro
  version: 1.0.0
paths:
  /hello:
    get:
      responses:
        '200':
          description: ok
          content:
            application/json:
              schema:
                type: object
                properties:
                  message:
                    type: string
                required: [message]
```

`hono-takibi.config.ts`:

```ts
import { defineConfig } from 'hono-takibi'

export default defineConfig({
  input: 'openapi.yaml',
  output: './src/routes.ts',
  template: {},
  client: { output: './src/client.ts', baseUrl: '/' },
  rpc: { output: './src/rpc.ts' },
})
```

## Actual

`src/handlers/hello.ts`:

```ts
import { OpenAPIHono } from '@hono/zod-openapi'
import { getHelloRoute } from '../routes'

const app = new OpenAPIHono()

export const helloHandler = app.openapi(getHelloRoute, (c) => {})
```

```
handlers/hello.ts(6,56): error TS2345: Argument of type '(c: Context<Env, "/hello", {}>) => void' is not assignable to parameter of type 'Handler<Env, "/hello", {}, MaybePromise<TypedResponse<{ message: string; }, 200, "json">>>'.
```

## Suggestion

A stub that throws compiles, because its return type is `never`:

```ts
export const helloHandler = app.openapi(getHelloRoute, (c) => {
  throw new Error('Not implemented')
})
```

With that body, the same project (template + client + rpc) has 0 errors. hono-takibi already keeps handler bodies
when it regenerates: bodies filled in by hand survived two regenerations in `apps/train-travel-client`, and the
second regeneration left every file unchanged. So a throwing default would not overwrite code that users wrote.

## Environment

- hono-takibi 0.32.6 (also 0.32.5), @hono/zod-openapi 1.6.3, TypeScript 7.0.2, Node.js 22, Linux
- Example app: `apps/train-travel-client` in nakita628/hono-takibi-examples. Its stubs are filled with
  `throw new Error('Not implemented')` so that it typechecks.
