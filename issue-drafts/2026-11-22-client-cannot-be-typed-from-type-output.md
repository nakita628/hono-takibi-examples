# Let `client` be typed from the `type` output, without `template`

## Summary

`type` writes the whole API as one type, `declare const routes: OpenAPIHono<…>` with `export default routes`.
That is what `hc<typeof routes>` needs. The generated `client` cannot use it:

- Without `template`, the config is rejected:
  `Invalid config: client needs template: the client is typed by the app the template scaffolds.`
- With `client.import: './types'`, the client imports `{ api }`, but `types.ts` only has a default export,
  so `tsc` fails with TS2614.

`rpc` and every hook import that client, so all of them are typed through the template's app, including its
unimplemented handler stubs (see the related draft about stubs).

## Reproduction

`openapi.yaml`:

```yaml
openapi: 3.1.0
info:
  title: client-repro
  version: 1.0.0
paths:
  /hello:
    get:
      responses:
        '200':
          description: ok
          content:
            application/json:
              schema:
                type: object
                properties:
                  message:
                    type: string
                required: [message]
```

`hono-takibi.config.ts`:

```ts
import { defineConfig } from 'hono-takibi'

export default defineConfig({
  input: 'openapi.yaml',
  output: './src/routes.ts',
  template: {},
  type: { output: './src/types.ts' },
  client: { output: './src/client.ts', baseUrl: '/', import: './types' },
  rpc: { output: './src/rpc.ts' },
})
```

## Actual

`src/client.ts`:

```ts
import { hc } from 'hono/client'
import type { api } from './types'

type Client = ReturnType<typeof hc<typeof api>>

const hcWithType = (...args: Parameters<typeof hc>): Client => hc<typeof api>(...args)

export const client = hcWithType('/')
```

```
client.ts(2,15): error TS2614: Module '"./types"' has no exported member 'api'. Did you mean to use 'import api from "./types"' instead?
```

Removing `template` from the config instead stops the run with the `client needs template` message above.

## What works

The same client written by hand against the default export typechecks with the generated `types.ts` and `rpc.ts`.
No template and no handlers are in the program:

```ts
import { hc } from 'hono/client'
import type routes from './types'

type Client = ReturnType<typeof hc<typeof routes>>

const hcWithType = (...args: Parameters<typeof hc>): Client => hc<typeof routes>(...args)

export const client = hcWithType('/')
```

`tsc --noEmit` over `types.ts`, this `client.ts`, the generated `rpc.ts` and a caller reports 0 errors. Reading a
field that does not exist (`body.nope`) fails with TS2339, so the types are real and not `any`.

## Suggestion

Allow `client` without `template` when `type` is configured, and generate `import type routes from '<type.output>'`
with `hc<typeof routes>`. Alternatively, have the `type` output also export the name the client imports.
Either way, `rpc` and the hooks would no longer depend on the template's handlers.

## Environment

- hono-takibi 0.32.6 (also 0.32.5), hono 4.13, @hono/zod-openapi 1.6.3, TypeScript 7.0.2, Node.js 22, Linux
- Example app: `apps/train-travel-client` in nakita628/hono-takibi-examples (`configs/parse-response.config.ts`
  keeps `type` and notes why the client is typed from the template instead)
